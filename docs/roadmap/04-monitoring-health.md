# 04 · 健康检查 / 延迟 / 测速 / 流量统计（P2）

> 分类：【待验证】方案 + 【参考提炼】判据（参考项目在这块踩过最严重的坑）。

## 1. 先定义口径，再谈采集【参考提炼】

| 指标 | 口径 | 不可混淆 |
|---|---|---|
| 节点流量 | sing-box `clash_api` connections 的 `downloadTotal`/`uploadTotal` 累计 | ≠ 服务商账单流量 |
| 账号账单流量 | Vultr/Evoxt API（现有 `/api/vps/usage`） | 含所有实例、按自然月 |
| 延迟 | TCP/TLS 握手或真实请求 RTT，**多采样取多数** | ≠ 吞吐 |
| 吞吐 | **加密多连接直连源站**测速 | 明文 HTTP 会被 DPI 降速，给出差百倍的假数据 |
| 可用性 | **e2e 探针**（经节点真拉源站） | 端口活 ≠ 能用 |

## 2. 探针设计（必须遵守）

1. **e2e 而非端口探活**：经 inbound 真拉一个源站，判断"能不能用"。
2. **多采样多数决**：单采样在丢包链路必然假阴性。参考项目曾因此把主力机**一天重启 66 次**，掐断全体用户。
3. **快降级慢恢复 + 非对称迟滞**：异常连续 N 次才判坏，恢复连续 M 次才判好（N>M 或相反按业务定）。
4. **抖动锁**：1h 内翻转 ≥3 次 → 静默该目标，等稳定自动恢复。
5. **哨兵出网自检门**：先探公共锚点（如 1.1.1.1 / 8.8.8.8 的 443）；全不可达 = 本机线路问题 → **跳过外探**，只发一条"哨兵出网异常"，避免全舰队误报。
6. **每目标只归一台哨兵**，避免双哨兵各发一遍；**不探自己托管的服务**。
7. **封锁判定防抖**：连续 2 轮 + >70% 不通才判封。

## 3. 自愈护栏（限的是动作，不是播报）

| 护栏 | 值（建议起点） |
|---|---|
| 重启最小间隔 | ≥10 min |
| 每日重启动作上限 | ≤3 次 |
| 整机重启 | **默认禁止**，需显式开关 + 最小运行时长 |
| 定时器 | 周期任务一律 `OnCalendar`；只用 `OnUnitActiveSec` 会卡 elapsed |
| docker 慢 ≠ 死 | **不要重启 daemon**（会放大成全站 outage） |
| 故障切换 | selector 零重启翻转；判据满足才切，切后观察期 |

## 4. 延迟测试 API 语义【参考提炼】

mihomo `/proxies/{name}/delay`：

| 情况 | 返回 |
|---|---|
| 缺 `timeout` 参数 | **400** |
| 超时 | **504** |
| 测试失败 | **503** |

→ 面板必须带 `timeout`，并区分"超时/失败/参数错"，不能一律显示"离线"。

**UDP 探活**：`nc -vzu` **不可靠**（无连接语义），不要用它判定 UDP 端口可用性；用真实协议握手。

## 5. 告警降噪

- 参考项目实测：一周 47 条 Telegram 告警，**实际需动手约 2 条**。
- 做法：目标级防抖 + 每目标单哨兵 + 出网自检门 + 分级（信息/警告/需动手）+ 聚合摘要。
- **好产品要安静**：告警数量不是健康度指标。

## 6. 面板侧实现建议

| 能力 | 数据来源 | 备注 |
|---|---|---|
| 节点在线/延迟 | sing-box `clash_api` `/proxies/{name}/delay`（经 SSH 隧道访问 127.0.0.1） | 必须设 secret；不绑 0.0.0.0 |
| 节点流量 | `clash_api` `/connections` 累计 | 重启会清零 → 需持久化累计基线 |
| 账号流量 | 现有 `/api/vps/usage` | **前置：服务商 API 白名单**（已验证根因） |
| 历史曲线 | 面板侧 SQLite 时序表 | 采样间隔 ≥60s，避免压垮 1 vCPU |
| 测速 | 手动触发，加密多连接直连源 | **不做定时自动测速**（耗资源、易误判） |

> ⚠️ 历史决策：面板的**订阅节点页曾取消延迟测试**（只读订阅工作台）。自建节点属我方自有资产，是否开放延迟测试需**重新确认边界**，不要默认沿用旧约束。

## 7. 验收

- 探针在人为丢包 30% 的链路上不产生误判。
- 自愈在人为故障下不超过每日上限。
- 告警在哨兵自身断网时只发一条。
- 流量曲线在 sing-box 重启后不断档（基线持久化）。
