# 01 新 VPS 接入

> 分类：【待验证】流程草案。步骤为通用做法，**每一步都要先获授权**。

## 前置

- [ ] 明确目标：这台机器承担什么角色（出口/中转/算力/落地）。
- [ ] 确认现有拓扑不会被影响（见 infrastructure/01）。
- [ ] 准备**独立** SSH 用户与密钥，**不复用** lucky-tunnel 的密钥。

## 步骤

| # | 动作 | 判据 |
|---|---|---|
| 1 | 只读巡检：`uname -a`、`cat /etc/os-release`、`nproc`、`free -m`、`df -h`、`ss -tulpn`、`ufw status verbose` | 记录基线，判断资源是否够跑目标协议 |
| 2 | 系统加固：非 root 管理用户、SSH 密钥登录、禁密码登录、fail2ban | 见 knowledge/01、09 |
| 3 | 防火墙最小放行：只开必需端口，**TCP/UDP 分别确认**；同时确认**云厂商安全组** | 云安全组与主机防火墙是两层，都要放行 |
| 4 | 内核参数：hy2 需 `net.core.rmem_max`/`wmem_max` = 16777216 | 东京实测基线仅 212992，必须先抬 |
| 5 | 端口占用检测：目标端口是否被现有服务占用 | Lucky 已占 TCP 443；UDP 443 空闲可共存 |
| 6 | 部署目标服务（钉版本镜像 + 独立 bridge + 显式端口） | `docker compose config` 通过 |
| 7 | 官方校验配置 | `sing-box check -C <dir>` 必须通过 |
| 8 | 启动 + 健康检查 + 端到端探活 | **端口活 ≠ 能用**，必须走客户端或 e2e 探针 |
| 9 | 纳入面板管理：登记主机、角色、端口、协议、凭据引用（不存明文） | 见 roadmap/03 |
| 10 | 记录到 infrastructure/04 与 troubleshooting/ | 含基线数字与验证结果 |

## 禁止

- 不用双栈域名（AAAA 指向家庭 NAS）定位 VPS 代理。
- 不创建无认证公开代理。
- 不在未备份的情况下覆盖现有服务配置。
- 不执行参考项目的安装器/一键脚本。

## 回滚

- 部署失败：停容器、恢复备份配置、关闭新开端口。
- 加固失败：保留一个已验证可用的 SSH 会话作为救援通道，**不要断开唯一连接**。
