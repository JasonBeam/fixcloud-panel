# 02 配置变更与回滚

> 分类：【我方已验证】判据 + 【待验证】流程。核心事务模型来自 FixCloud 现有 save_service。

## 事务 11 步（沿用现有实现，不另造）

1. 重读当前配置并计算 hash（防并发覆盖）。
2. 在内存中做结构化修改（保留未知字段）。
3. 生成**完整 Diff** 供评审。
4. 语法校验 + 引用完整性校验。
5. 按策略备份（时间戳目录）。
6. 写临时文件（同目录，保证原子 rename）。
7. 回读临时文件校验。
8. 安全替换（`os.replace`）。
9. 回读正式文件校验。
10. 失败时区分三态：**unchanged（未替换）/ restored（已恢复）/ recovery_failed（需人工）**。
11. 审计记录（**不记凭据明文**）。

## 远端（VPS）配置变更额外要求

| 要求 | 做法 |
|---|---|
| 官方校验 | `sing-box check` 必须通过才允许替换 |
| 判重 | hash 相同则**跳过**，不重载（SIGHUP 会断存量连接） |
| 原子写 | 临时文件 + rename；权限 0600 |
| 泄露断言 | 渲染/替换前扫描输出，命中敏感字段则拒绝 |
| 整批回滚 | 多机同步时 check 不过则**整批回滚**，不做部分成功 |
| 重载 | SIGHUP；**没有 reload 子命令**；Clash API `PUT /configs` 是空操作 |
| 重载后验收 | 探活 + 客户端实测；不能只看进程在跑 |

## 回滚

- 配置回滚：恢复备份目录 → 再 check → SIGHUP。
- 镜像回滚：改回上一个 tag → `up -d`。
- **回滚也要验收**，不能假设"恢复备份就好了"。

## 禁止

- 不自动格式化用户手写配置（历史决策：未知字段无损保留）。
- 不在列表页放全局保存；保存必须进 Diff 评审。
- 不用重启掩盖配置错误。
