# 04 故障响应

> 分类：【我方已验证】原则 + 【参考提炼】教训。

## 第一步：只读，不重启

1. 读当前状态（见 05 只读巡检）。
2. 判断影响面：谁受影响、是否全站、是否只影响某条线路。
3. **不要用重启掩盖问题**。参考项目教训：docker 慢 ≠ 死，重启 daemon 会把局部问题放大成全站 outage。

## 第二步：定位层级

| 层 | 检查 |
|---|---|
| 客户端 | 版本、订阅是否更新、规则是否命中 |
| 订阅/配置 | 内容是否被改、hash 是否漂移、是否含错误字段 |
| 网络路径 | DNS 解析（A/AAAA 分别看）、路由、是否被 OpenClash 接管 |
| 防火墙 | 主机 ufw/nftables + **云安全组**（两层） |
| 服务 | 进程/容器状态、端口监听、日志 |
| 上游 | 服务商 API/账单、IP 是否变化、是否被封锁 |

## 第三步：判定是否"被封锁"

- **连续 2 轮 + >70% 探测点不通**才判封，避免抖动误判。
- 单采样在丢包链路必然假阴性 → **多采样多数决**。
- 拿到 STUN 映射 ≠ 外网可达。
- 端口活 ≠ 能用 → 必须 e2e。

## 第四步：最小修复

- 优先**零重启**手段（selector 翻转、规则调整）。
- 需要重启时：先备份、先确认救援通道、限定间隔（≥10min）与每日上限（≤3）。
- 防火墙改动用**精确 insert + comment**，回退按 handle 删除；**禁止清空整链/flush**。

## 第五步：验收与记录

- 分层报告：已定位 / 已修复 / 已实测 / 未覆盖场景。
- 写入 troubleshooting/：现象、根因、解决方法、验证结果、预防措施。
- 若是自愈逻辑误动作，**同时修护栏**，不只修这一次。

## 告警降噪

- 限的是**动作**不是播报。
- 哨兵先自检出网（公共锚点全不可达则跳过外探，只发一条汇总）。
- 每个目标只由一个哨兵负责，不探自己托管的服务。
- 1 小时内翻转 ≥3 次进入静默锁。
