# 01 面板核对公开订阅 URL 超时

> 分类：【我方已验证】。环境：QNAP NAS + bridge 网络面板容器 + host 网络 Lucky。

## 现象

面板侧核对"公开文件 URL 与本地主 YAML 是否一致"时超时；但同一 URL 从外部访问正常。

## 影响面

只影响面板自身的一致性核对功能；不影响外部客户端订阅拉取。

## 排查过程（只读）

| 探测 | 结果 |
|---|---|
| 容器 → 公网 IPv6 站点 | **通**，200 / 0.16s |
| 容器 → NAS 自身公网 IPv6（即该文件域名解析到的地址） | **不通** |
| 宿主机 → 公网 IPv6 出网 | **超时** |
| 外部 → NAS 入站 | **在线**，0.13s / 200 |

## 根因

域名解析到 NAS 自身的公网 IPv6。容器访问"自己的公网地址"时，流量需要经宿主机回环投递；该路径在本环境不通（宿主机 IPv6 出网本身超时）。
**不是 DNS 错、不是证书错、不是服务挂了**——外部访问完全正常。

## 解决方法（最小改动）

给面板容器加 `extra_hosts`，把该文件域名指到 **bridge 网关的 IPv6 地址**：

```yaml
extra_hosts:
  - "<PUBLIC_FILE_DOMAIN>:<BRIDGE_GATEWAY_IPV6>"
```

因为 Lucky 以 host 网络监听 `:::443`，投递到网关地址即可命中本机服务。

**验证结果**：`matching: true`，87ms。

## 为什么不用 NAT66

QNAP 上 `sudo` 需要密码、根文件系统是 ramdisk，改宿主机防火墙/NAT 的成本与风险都高于容器侧一行 `extra_hosts`。

## 预防措施

- 一致性核对这类"自己访问自己的公网域名"的功能，**默认就要考虑回环投递问题**。
- 更根本的解法：让核对走**本地文件比对**或内网地址，不依赖公网域名（见 roadmap/01 私有订阅改造）。
